## Defects (ranked)
1. **INT4 shadow is dummy-loaded under verl (CRITICAL, vLLM C2).** `vllm/model_executor/dual_precision/loader.py:211-238 make_int4_vllm_config` clones `vllm_config` including `load_config`; verl's rollout `load_format: dummy` (every C9 overlay except phi4; verl's default) makes `load_int4_shadow_model` (loader.py:247) use the DummyModelLoader: the log shows "Loading dual precision INT4 shadow model" with no "Loading weights took" line, and every INT4-phase token is multilingual garbage (B3: 62/64 cap hits, reward 0; A: post-switch tails garbage). Standalone probe (load_format auto) is coherent fresh, after sleep(1)/wake and after load_weights; with `rollout.load_format=auto` B3'/A'/C' are coherent (B3 reward 0 -> .59, A cap hits 15 -> 6, reward .78 -> .91). The archived lane worked only because it set ROLLOUT_LOAD_FORMAT=auto. Fix: in make_int4_vllm_config clone `load_config` with `load_format="auto"` (the shadow always comes from its checkpoint) and refuse `dummy`; additionally have the recipes set `validate_shadow=true` (its cosine check would have caught this at attach) and/or set `load_format: auto` in the overlays.
2. **Experiment name from a policy path (HIGH, verl C10).** `examples/precision_scheduler/common.sh:96` `PS_EXPERIMENT_NAME="${EXPERIMENT_NAME:-${model_key}_${POLICY:-bf16}}"`: a JSON policy puts `/` into `trainer.experiment_name`; FileLogger open() fails 7 min in (after engine init), every `.json` launch (rollout_only, full_step, continuous_ema) dies unless EXPERIMENT_NAME is exported. Fix: use `${PS_POLICY_KIND}` or `$(basename "${POLICY%.json}")`; add a CPU test that the name matches `[A-Za-z0-9_.-]+`.
3. **Contract log lines invisible at verl's default log level (MEDIUM).** verl sets `VLLM_LOGGING_LEVEL=WARN` (constants_ppo.py:44); the clean switch/reload/arm lines are `logger.info` (`vllm/v1/core/sched/precision_switch.py:215`) and the bind line is `logger.info` (`vllm/model_executor/dual_precision/binding.py:296`), whereas the archived contract lines were WARNING. Consequences: `validate_rollout_run.py --expected-lora-layers` (tools/validate_rollout_run.py:126-130) can never pass from a recipe launch, and the "SWITCH_RE verbatim" contract only holds if the user exports VLLM_LOGGING_LEVEL=INFO by hand (I did). Fix: log the switch, reload and bind lines at WARNING (as archived) or emit VLLM_LOGGING_LEVEL from the precision_scheduler block.
4. **Lifecycle probes run before the lifecycle (MEDIUM, C2 validation).** `validate_shadow_lifecycle` fires at the first INT4 bind (binding.py:268-271), which is the CUDA-graph capture during engine init, before any sleep/wake or weight sync; the "exact=True" line therefore proves nothing about the shadow at rollout time (it was exact=True while the shadow was random dummy weights). Fix: re-run the probes at the first INT4 bind *after* each wake-up / update_weights, or at the first switch of every rollout.
5. **continuous_ema.sh RUNNER=full_step ignores INITIAL_BATCH (LOW, C10).** `recipes/continuous_ema.sh:43` passes INITIAL_BATCH to the runner and `--batch` to the watcher, but full_step.sh/run_fsdp_fullstep.sh read TRAIN_BATCH_SIZE (default 16): with INITIAL_BATCH=32 the watcher counts steps in groups of 32 while the trainer submits 64, so completed_steps double-counts and the policy's cohort size disagrees with B. I exported TRAIN_BATCH_SIZE=16 to keep them consistent. Fix: derive TRAIN_BATCH_SIZE=INITIAL_BATCH/ROLLOUT_N in continuous_ema.sh for both runners.
6. Note (not a defect): fixed_frontier:K at B64 switches only once live <= capture_max_batch (32): B2 committed 2000, applied 2796 at live 32; identical to the archived fixed_k8000.json guard (capture_max_batch 32).
